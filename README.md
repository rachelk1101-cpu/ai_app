# 튼튼이와 운동해요

발달장애인이 혼자서도 따라 할 수 있는 운동 웹앱. 사람 대신 **3D 캐릭터 튼튼이**가
동작을 보여 주고, 카메라로 자세를 인식해 **즉각적인 칭찬**을 준다.

창업경진대회 출품용. **4주 · 28회차 프로그램**이고, 한 회차는 운동 5가지 · 2~3분이다.
시작부터 칭찬 화면까지 끊김 없이 돌아가며 진도는 브라우저에 저장된다.

---

## 실행

```bash
npm install
npm run dev             # http://localhost:5173
npm run dev -- --host   # 같은 Wi-Fi 의 태블릿에서 열 때
```

`npm run dev` / `npm run build` 는 실행 전에 `npm run setup` 을 자동으로 돌려
MediaPipe 런타임과 모델(합계 42MB)을 `public/mediapipe/` 에 준비한다. 이 파일들은
git 에 넣지 않는다 — WASM 은 `node_modules` 에서 복사하고 모델은 공개 주소에서
받으므로 언제든 다시 만들 수 있다.

```bash
npm test         # 자세 판정 로직 테스트
npm run build    # 타입 검사 + 프로덕션 빌드
npm run preview  # 빌드 결과 확인
```

카메라를 쓰므로 `localhost` 또는 **HTTPS** 에서만 인식이 동작한다.
`--host` 로 띄운 주소(`http://192.168.x.x:5173`)는 HTTPS 가 아니라서
다른 기기에서는 화면만 보이고 자세 인식은 되지 않는다. 태블릿에서 인식까지
확인하려면 배포된 주소로 접속할 것.

## 배포

Vercel 에 배포한다. 저장소를 연결해 두면 `main` 에 push 할 때마다 자동으로
다시 배포된다.

빌드는 `npm run build` 를 그대로 쓴다. `prebuild` 의 `npm run setup` 이
MediaPipe 파일을 준비하므로 별도 설정이 필요 없다.

하위 경로로 서빙하는 곳(GitHub Pages 의 `/<저장소>/` 같은)에 올릴 때는
`BASE_PATH=/저장소이름/ npm run build` 로 base 를 덮어쓴다. 코드가
`import.meta.env.BASE_URL` 을 쓰고 있어 그것만 바꾸면 된다.

## 설계 원칙

### 실패가 없다

이 앱의 가장 중요한 규칙이다. **자세 인식은 칭찬을 주는 데만 쓰고, 진행을 막는 데는
쓰지 않는다.**

한 회차는 캐릭터 동작 한 사이클이고 항상 그 시간만큼 걸린다. 자세를 해내면 그 순간
칭찬이 나가지만, 해내지 못해도 회차는 똑같이 끝나고 별도 똑같이 받는다. "틀렸어요",
빨간색, X 표시는 어디에도 없다.

발달장애인 사용자에게 '못 해서 멈춘 화면'은 그 자리에서 앱을 그만두게 만드는 가장
확실한 방법이기 때문이다. 같은 이유로, 랜드마크를 못 봤을 때(팔이 화면 밖으로 나감,
몸에 가려짐)는 **실패가 아니라 통과**로 처리한다 — 사용자가 못 한 것이 아니라
우리가 못 본 것이다.

### 앞으로 일어날 일을 미리 다 보여 준다

고르기 화면에서 오늘 할 운동 5가지를 순서대로 다 보여 준다. 운동을 직접 고르게
하지 않는 것도 의도적이다. 선택지보다 예측 가능성이 중요하다.

### 날짜가 아니라 회차로 센다 — 연속 출석은 없다

한 달 프로그램이지만 달력 날짜로 진행하지 않는다. 날짜 기준이면 사흘 쉬었다
들어온 사용자가 갑자기 4일차로 건너뛴다. 못 한 날이 눈에 보이고 따라잡을 수도 없다.

회차로 세면 오늘 하면 도장이 하나 찍힐 뿐이다. 일주일을 쉬어도 이어서 하면 된다.
**연속 출석(스트릭)을 두지 않는 것**도 같은 이유다 — 하루 빠졌다고 쌓아 온 것이
0 으로 돌아가는 경험은 그 자리에서 앱을 그만두게 만든다. 빈칸에는 X 도 빨간색도 없다.

### 반복이 지루함이 아니라 학습이다

1주와 2주는 운동 구성이 똑같고 횟수만 는다. 새 동작은 3주에 둘, 4주에 하나만
들어온다. 매주 다섯 개가 전부 바뀌면 한 달 내내 '익숙해지는 경험'을 한 번도 못 한다.

### 화면 규칙

`src/ui/tokens.ts` 에 상수로 고정해 두고 공용 컴포넌트가 강제로 적용한다.

- 한 화면에 누를 수 있는 것은 1~2개
- 버튼 최소 높이 88px, 본문 최소 24px
- 문장은 한 줄, 짧은 평서문
- 그림과 글자를 항상 함께
- 깜빡임·빠른 전환·큰 소리 없음
- 화면 순서는 절대 바뀌지 않음

### 프라이버시

카메라 영상은 기기 밖으로 나가지 않는다. MediaPipe WASM 과 모델 파일을 모두
`public/mediapipe/` 에 번들해 두어서, 인터넷이 끊긴 곳에서도 동작하고 프레임이
서버로 전송되는 경로 자체가 없다. 음성 안내도 브라우저 내장 TTS 라 외부로 나가는
요청이 없다.

## URL 파라미터

개발과 시연에 쓴다.

| 파라미터 | 예시 | 설명 |
|---|---|---|
| `screen` | `?screen=workout` | 원하는 화면부터 연다 (`home`/`pick`/`workout`/`reward`) |
| `mock` | `?mock=1` | **시연 모드.** 카메라를 켜지 않고 시간에 맞춰 성공 신호를 만든다 |
| `day` | `?day=16` | 16번째 날부터 시작한 것처럼. 도장이 쌓인 화면을 바로 보여 줄 때 |
| `pose` | `?pose=armsUp` | 동작 키프레임을 한 사이클 펼쳐 보는 개발용 화면 |
| `turn` | `?pose=march&turn=35` | `pose` 화면에서 캐릭터를 돌려 본다 |

`?day=` 는 저장된 진도를 덮어쓰기만 하고 저장하지는 않는다. 시연으로 사용자의
실제 기록이 망가지지 않는다.

**`?mock=1` 은 대회 발표용 보험이다.** 대회장 조명이 어둡거나, 카메라 권한이
막히거나, 사람이 붐벼서 전신이 안 잡히는 일은 실제로 자주 일어난다. 그때도
전체 흐름이 그대로 재생된다.

### 캐릭터에 에셋 파일이 없는 이유

튼튼이는 GLB 모델이 아니라 **구와 캡슐로 코드에서 조립한 캐릭터**다. 동작도
Mixamo 클립이 아니라 관절 회전 키프레임을 손으로 적은 것이다(`poses.ts`).

이렇게 한 이유는 3D 에셋 파이프라인(모델 확보 → Mixamo 리깅 → Blender 병합)이
이 프로젝트의 유일한 비(非)코드 작업이고, 그게 일정을 막으면 아무것도 못 만들기
때문이다. 지금 방식은 파일 의존이 없어서 어디서든 바로 돌아가고, 속도·시점 각도·
중간 정지를 코드에서 완전히 통제할 수 있다.

나중에 GLB 로 바꾸려면 `Character.tsx` 만 교체하면 된다. `CharacterStage` 의
인터페이스(`clip`, `phaseRef`, `turnDeg`, `mirrored`)는 그대로 쓸 수 있다.

### 이 체형에서 지켜야 할 동작 제약

튼튼이는 머리가 키의 40% 가 넘는다. 그래서:

- **팔을 160° 이상 들면 머리 뒤로 숨는다.** 만세는 곧게 위가 아니라 125~140° 의 V자.
- **두 손을 맞댈 수 없다.** 팔 길이 0.62 로는 머리 위에서도, 반대쪽 어깨에서도
  손이 만나는 지점이 몸 안쪽이 된다. '머리 위 박수'와 '나를 안아주기'를 넣으려다
  둘 다 이 이유로 접었다.
- **앞으로 뻗는 동작은 정면에서 안 보인다.** 카메라 쪽으로 단축되기 때문. 손뼉·제자리
  걷기는 `viewAngle` 로 30~35° 돌려서 보여 준다.
- **어깨를 크게 돌려 놓으면 팔꿈치를 X 로 접을 수 없다.** 로컬 축이 같이 돌아가서
  앞뒤로 접히기 때문. '알통 만들기'처럼 팔을 옆으로 벌린 자세에서는 Z 로 접어야 한다.

새 동작을 추가할 때는 `?pose=<클립이름>` 으로 **반드시 눈으로 확인할 것.** 숫자만
보고는 팔이 머리에 가려지는지, 카메라 쪽으로 단축되는지 알 수 없다. 위의 제약은
전부 이 화면에서 발견한 것이다.

## 아직 안 한 것

- 보호자·교사용 기록 화면 (어떤 동작을 어려워하는지)
- 여러 사용자 · 기기 간 진도 동기화 (지금은 이 브라우저에만 저장된다)
- 2개월차 이후 프로그램
- 캐릭터 커스터마이징
- 앱 포장 (PWA 또는 Capacitor)
- 카드용 그림을 이모지에서 일러스트로 교체
